Juben Deconstruct · 剧本拆解工作流

核心立场：任务不是「把资料转成文字」，是让一个人能独立带完全场。 转写只是原料，交付物必须回答：人物是谁、时间线怎么走、真相几层、线索指向什么、主持时什么时候做什么、哪里会翻车。

何时使用

  • 用户丢来一个剧本资料包，说「读一下 / 转成 md / 我想学 / 我要当 DM」
  • 用户要给别人（同事、学生、协作者）做学习资料
  • 用户想把一个本沉淀成可对比、可迭代的知识资产
  • 与 maieutic-skill 配合：本 skill 负责产出资料，maieutic 负责带着人学会

八阶段流水线

#阶段关键动作产出
1盘点与去重递归列文件、按扩展名分类、MD5 比对多份资料包，找出唯一完整真源；记录缺口（如手册说 35 张卡但只有 18 张图）文件清单 + 体积 + 去重结论
2版面探测判断文字层 / 扫描件 / 拼版结构；抽样测 OCR 质量与单页耗时后再定批量参数决策表（见下）
3全量转写PDF 文字层直提；扫描件 OCR；图片 OCR；音视频抽音轨 ASR + 抽帧 OCR按资料分组的 md + _raw/ 纯文本
4阅读顺序校正骑马订 2-up 拼版必须按印刷页重排；图片按文件名中的数字排序（不能字典序）顺序正确的 md，保留原序备份
5知识重组先读组织者手册（真相/流程/线索逻辑通常全在这里），再读角色本补第一视角任务，最后读线索卡人物档案、时间线、真相、诡计、线索→结论表
6剧透隔离（对外必做）按 🟢无剧透 / 🟡主持须知 / 🔴全剧透 分文件，导读里写明「哪份可以给谁」可直接转发的学习包
7归纳卡片五维归纳：结构 / 真相 / 诡计 / 线索 / 主持；填跨本对比矩阵07_归纳卡片.md
8入库与回填剧透资料进私有仓库，方法论与工具进公开知识库；开本后回填现场翻车点commit + push + CHANGELOG

版面探测决策树

情况判据处理
PDF 有文字层pdftotext 前两页能抽出非空白中文直接提取，保留表格结构
PDF 是扫描件抽不出文字，但 get_images 有大图渲染 → OCR
骑马订 2-up 拼版一张 A3 上左右两栏，页脚数字分别是 1 和 32、2 和 31按中缝切栏 → 用页脚数字还原印刷页 1→N
纯 JPG 扫描包全是 5100×7014 之类高清单页按目录分组、按数字排页序，OCR
2×2 拼版线索卡一张图上 4 个证据块，手册却说卡有 35 张别按「图数=卡数」计数，OCR 全抓后按手册编号体系整理
音视频线索ffprobe 看时长与音轨抽音轨 ASR ＋ 每 4 秒抽帧 OCR；纯视觉线索必须人工/多模态看图补

无声视频是最大的暗坑：很多线索既无台词也无字幕，情报在「看见了什么」（如眼球泡在防腐液盒里、招牌写着十年老店）。只做 ASR 会漏掉官方点名的推理支点。

工具箱

脚本随 skill 放在 tools/，路径全部参数化，不写死盘符。

脚本用途典型调用
scan_ocr_pipeline.py纯 JPG/PNG 扫描包 → 分组 md；数字排序、行聚类还原段落、多进程python tools/scan_ocr_pipeline.py --src <资料包> --out <输出> --workers 6
ocr_pipeline.pyPDF 扫描件 → md；双栏切分、页脚识别；JUBEN_SRC/JUBEN_OUTJUBEN_SRC=... JUBEN_OUT=... python tools/ocr_pipeline.py --workers 6
reorder_imposition.py骑马订 2-up → 印刷页顺序重排在 OCR 产物目录上运行
text_docs.pyPDF 文字层 / DOCX / TXT → 结构化 md同上环境变量
video_frame_ocr.py视频抽帧 + 画面文字 OCRpython tools/video_frame_ocr.py --src <视频目录> --out <md> --interval 4
AudioTranscribe音频/视频台词转写（先 ffmpeg 抽 16k 单声道 mp3 更稳）逐文件调用

环境：pymupdf pillow numpy onnxruntime rapidocr_onnxruntime python-docx pyyaml；外部命令 pdftotext / ffmpeg / ffprobe。

性能要点：ONNX 推理必须每进程单线程（patch SessionOptions.intra_op_num_threads=1），多进程并行；否则线程争抢会让 300 页从 5 分钟拖到 20 分钟以上。缩放长边 2000px 是精度/速度平衡点。

转写层  01_角色剧本 / 02_线索卡 / 03_开本资料 / _raw/   ← 可检索、可喂模型
应用层  00_DM主持学习手册 / 00_开本速查卡 / 对外学习包   ← 学会 + 带本
归纳层  07_归纳卡片 / 跨本对比矩阵                       ← 越学越省力

剧透隔离（对外交付的硬规则）

必须做文件级隔离，不要只在一篇文档里加「以下剧透」——转发出去就收不回。

标记内容可给谁
🟢导读、本作是什么、学习路径、无剧透自测任何人，含准备上车的玩家
🟡流程、发本题答案、线索发放规则、角色定位表仅主持人
🔴真相、时间线、诡计、排除法、音视频指向主持人 / 已玩完想复盘者

导读里必须写一张「哪份可以给谁」的表，以及一句「不要把后面几册发给还没玩过的人」。

对外文档去 PM 化清单

给同事／学生／协作者的文档里，以下一律不出现：

  • 本地绝对路径、盘符、_raw/、~/.workbuddy/skills/ 等目录名
  • 「OCR」「ASR」「转写」「抽取」「重排」「可信度 A/B/C/D」「来源文件」「rename mapping」等内部术语
  • 「入库」「归档」「commit」「push」「仓库」「去重」「流水线」等项目管理词
  • 任务编号、工具脚本名、报错日志、页码溯源标记

替换说法：想说明准确性，写「本文依据官方手册整理，个别字词以原册为准；涉及投票判定与编号时请与原册核对」。想说明视频线索，写「部分视频为纯画面线索，请回看原视频」，不要写「帧 OCR 未检出文字」。

内部索引（cases/<本>/README.md）才负责记录来源、体积、提取方式与可信度；两份文档各司其职，不要混成一份。

质量校验清单

  • 所有页 with_text 数 = 总页数，或明确列出空白页；errors = 0
  • 拼版已按印刷页验证衔接（上一页末句 → 下一页首句能连上）
  • 角色任务、个人要隐藏的事，逐人逐幕对齐
  • 官方手册里点名的音视频线索，逐条有对应解释
  • 剧透红绿灯表格存在，且文件本身命名能看出级别
  • 对外版全文搜索 C:\、OCR、_raw、git、入库 → 0 命中
  • 私有仓库 isPrivate: true 已核验；公开知识库只放方法论与脚本，不放剧透
  • 归纳卡片已填，跨本对比矩阵已更新，CHANGELOG 已记

常见坑（两本实战验证）

  1. 两份资料包不是互补而是副本：MD5 全比对，选文件数更多的那个当唯一真源。
  2. 人数陷阱：剧本里出现「7 名玩家」不代表 7 人本，NPC 可能由 DM 扮演；以手册为准。
  3. 线索编号两套体系：「线索 32」可能指虚拟世界线索而非总表，勘误要对照手册读。
  4. 同批卡的不同打印版：A4 / B5 / 全尺寸三套别重复发。
  5. 推理线程争抢：见「性能要点」。
  6. 中文路径：用 PowerShell 直接传 Unicode 建目录联接，别写含非 ASCII 路径的 .bat / .ps1 脚本，编码会花。
