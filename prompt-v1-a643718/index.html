外来 prompt 不做配方物料 · 建目录第一件事写来源

入档:2026-08-03 触发:56_满堂 按自写作品的默认打法建了全套配方物料,想起 prompt 是朋友给的后整套作废 主线作品来源:{AIGC工作站}/56_满堂_90s港片古装人像_作品图文/ 验证状态:⚠️ 首次发现(1 次)

一句话

归档一个作品前先问「这条 prompt 是谁的」。外来 prompt(朋友给的 / 私下流传的)一律不做配方物料——不做配方卡、不做逐层拆解、不做「配方拆给你」式收藏钩子;只留看图能得出的视觉机制,那是自己的观察,可留可用可讲。

案例:做完了才撤

56_满堂 的 prompt 是朋友给的。但建仓时直接套用了 51_我不知道怎么形容花 的打法(那条 prompt 来自 MJ 官网,人人可见),做出了:

  • 轮播_03_配方卡_3x4.png(配方卡配图)
  • make_recipe_card.py(109 行生成脚本)
  • prompt复原与三层拆解.md
  • 正文末尾的「配方拆给你(可直接套)」段

整套作废。撤回时做了三件事,缺一不可:

动作为什么
删配图 + 删脚本配方卡是可传播的图片,留着随时会被误发;脚本留着等于配方还能重建
「prompt 复原与三层拆解」→ 重写为「prompt 来源与视觉拆解」只留看图得出的机制(前景遮挡、长焦压缩、景深),不逐字复原、不重建成可分发的配方
正文删掉配方段,收藏钩子改由画面和文案承担见 作品线与配方线外壳不串味_v1

成本本可为零——建目录时问一句就行。

为什么「拆解」和「复原」必须分开

这是本条最容易含糊的地方:讲机制 ≠ 泄配方。

可以做不可以做
内容「左边那团红是焦外前景遮挡物,镜头在人群里」逐字复原 prompt、给出可粘贴的完整句式
依据看图能得出,是自己的观察来自别人写的那串字
归档可写进项目文档,可讲给读者只留内部检索用的残片(job id / 文件名截断),标「完整原文未留存」

判据:这段东西,别人不看原 prompt、只看成图,能不能自己推出来? 能 → 是你的观察,可讲;不能 → 是他的配方,不碰。

如何使用 · 三步

  1. 建目录时,README.md 第一段就写明 prompt 来源:自写 / 外来 / 公开来源。写在最前面,后面所有物料决策都读它。
  2. 外来 → 物料清单当场划掉:配方卡、拆解文档、正文可复跑 prompt 段。收藏钩子改由画面 + 文案承担。
  3. 想讲方法,另起一条自写 prompt 的作品去讲,不要在这条上找补。

反例 / 边界

  • 公开来源不受此限:MJ 官网 explore 上人人可见的 prompt(如 51 项目那条散文式 prompt),仍可拆、可分发、可做配方钩子——它本来就是公开的。
  • 本条管的是分发,不是使用。朋友给的 prompt 自己拿来出图没问题,不能做的是把它包装成可传播的配方物料。
  • 只在 1 个项目上验证过,是「一次踩坑后立的规矩」,不是跨场景铁律。
