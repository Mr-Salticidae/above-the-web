《满堂》复盘 · 来源约束与文风归位（2026-08-03）

入档:2026-08-03 事实结果:

  • 作品:《满堂》(90s 港片古装人像,MJ 单次临时抽卡)
  • 发布:2026-08-03 刚发布,赞/藏/评/是否限流全部未知
  • 数据来源:无。本篇是生产过程复盘,不含任何效果判断
  • 关键前置事实:同类写实古风人像《孤鸿》(2026-06-22 批次)发布后被限流,限流归因未经平台确认 主线作品来源:{AIGC工作站}/56_满堂_90s港片古装人像_作品图文/复盘_2026-08-03_来源约束与文风归位.md 性质:作品归档与发布物料的流程复盘

一句话

一个作品该做什么物料、用什么文风,在动笔前就由两件事定死了:prompt 是谁的(决定能不能拆配方),这条属于哪条线(决定文案是散文诗还是配方帖)。这两问漏了,做完的东西要整套撕掉重来。

本次的实际代价:一张配方卡配图 + 109 行生成脚本 + 一篇拆解文档全部作废,外加一次正文重写。

一天三次转向

阶段做了什么
一、按「配方线」建仓照搬 51_我不知道怎么形容花 的打法:配方卡配图 + prompt 三层拆解 + 生成脚本,正文末尾「配方拆给你」
二、整套撤回想起 prompt 是朋友给的、不外传 → 删配图、删脚本、把「prompt 复原与拆解」重写为「prompt 来源与视觉拆解」(只留自己看图得出的机制)
三、文风返工作者一句「太正式了,参考之前衔风等系列」→ 正文由画面分析文改写为第一人称散文诗,机制降级为可选的评论区一条

两次返工都不是执行质量问题,是前置判断缺位。

沉淀出的两条律

各自已抽成独立档:

  • 外来prompt不做配方物料_v1 —— 开工前先问「这条 prompt 是谁的」,外来 prompt 一律不做配方卡 / 不做逐层拆解 / 不做「配方拆给你」钩子
  • 作品线与配方线外壳不串味_v1 —— 作品线只给画面和第一人称的声音,配方线才在末尾给可复跑配方;拿作品线的图配教程线的文,读起来就是「太正式」

第三条:写实 AI 人像限流 —— 只是假说 ⚠️,不单独立档

假说:写实向 AI 人像在小红书可能触发降权。

证据:《孤鸿》(写实古风男像)发布后被限流,共 1 例,且平台从不告知原因——可能是写实人像判定,也可能是题材 / 标签 / 账号状态 / 别的任何东西。

为什么不立档:1 例 + 归因未确认,按 复盘事实先行原则_v1 只能当「值得继续观察的假设」,不足以指导决策。硬立成律会让后续项目照着一个未验证的因果做减法。

但自查清单照做——成本极低,假说不成立也无损:

  1. 发布时如实勾选「内容由 AI 生成」,不让平台自己判;
  2. 文案避开「真人写真 / 实拍」话术,不暗示是真人照片;
  3. 不带艺人名、不做「撞脸」联想;
  4. 首图不裁成只剩脸的大特写,保留服装和环境。

下一次验证点:《满堂》的实际表现。同样被限流 → 升 ⭐⭐;正常 → 说明《孤鸿》另有原因,假说推翻重查。

元层:一条没记的事实,污染了两个月后的判断

《孤鸿》被限流这件事,从 6 月发布到 8 月一个字都没进归档。后果在本次原地引爆:

  • 《满堂》的发布文案里写成「上一条写实古风男相**「惊鸿」因违规没发出去**」——名字错了,结果也错了;
  • 连带一个决策失据:《满堂》原定名「惊鸿」,改名理由记为「与旧作重名」——可旧作叫《孤鸿》,根本不重名,改名理由不成立(名字保留了,因为「满堂」确实更贴画面);
  • 更实际的伤害:「没发出去」是显性拦截,「限流」是隐性降权,两者的自查重点完全不同。照着错的事实做合规,查的方向都是歪的。

修法(已落地,按 复盘事实先行原则_v1 「不覆盖原文、单独标勘误」):项目 README 加勘误块,回 48_即兴抽卡 给《孤鸿》补记限流事实与「归因未经平台确认」的限定。

规则:发布后 24h 内回填一行结果(发了没 / 有没有异常 / 数据),成本几乎为零。作品归档最容易漏的不是过程,是结果——过程当天就写了,结果要等,一等就忘。
