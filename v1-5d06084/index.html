代码排版小红书封面 · 工作流与复盘

首次记录：2026-06-17 来源：「牧云人」独立作品封面制作（一张 MJ 雾山牧羊原图 → 小红书封面 + 无字壁纸 + 发布文案） 状态：流程已跑通，跨”单张原图 → 排版封面”场景通用 配套代码：06_代码/46_牧云人封面/make_cover.py / 06_代码/46_牧云人封面/make_clean.py（镜像于 06_代码/46_牧云人封面/）

一句话

用 Pillow 代码排版做封面，比丢进设计软件更适合”批量、可复现、参数化微调”的封面生产——但前提是先解决三个隐形卡点：找回原图、保住高光、去掉水印。

卡点 1：粘贴进对话的图，不在磁盘上

用户把图直接粘贴到对话里时，它不会落成一个可访问的文件。实测排查路径：

  • %TEMP% 下的 .tmp / .webp：要么被进程独占（PermissionError），要么是 UI 切片、图标缩略（48×4032、100×100），都不是原图。
  • 会话临时目录 …/claude/<session>/：只有 tasks/，没有图。

结论：别在 temp 里捞。可靠做法是去用户指定的真实目录（这次是 Downloads）做视觉检索——

# 对目录里最近 N 张图拼一张 6×4 缩略接触表, 一眼定位
files = sorted(imgs, key=os.path.getmtime, reverse=True)[:24]
sheet = Image.new('RGB', (6*200, 4*200), (30,30,30))
for i,p in enumerate(files):
    t = Image.open(p).convert('RGB'); t.thumbnail((192,174))
    sheet.paste(t, ((i%6)*200+4, (i//6)*200+4))
    draw.text(..., str(i)+':'+os.path.basename(p)[:22])  # 标号+文件名

靠文件名猜会漏（MJ 文件名是 a_tiny_lost_cloud_resting_on_a_grassy_hills_…，跟”牧羊/老人”对不上），接触表一眼就锁定。这是本次最省时间的一招。

卡点 2：暗角要保高光，不能全图压暗

封面文字压在画面上要保证可读，但全图盖一层暗色 scrim 会把云朵/主体高光一起压灰，破坏氛围。

做法：以”文字所在的角”为中心的椭圆衰减暗角，只压那个角，云朵（画面中心）和人物（右侧）原样保留。

# 左上角椭圆暗角: alpha = clip(1 - ((x-cx)/rx)^2 - ((y-cy)/ry)^2, 0,1)^1.6 * amax
yy, xx = np.mgrid[0:h, 0:w]
d = ((xx-cx)/rx)**2 + ((yy-cy)/ry)**2
a = np.clip(1-d, 0, 1)**1.6 * amax        # 指数 1.6 让边缘更柔

颜色用深蓝灰 (18,26,36) 而非纯黑，跟雾蓝调一致，不发脏。

卡点 3：边缘水印——裁切 > 克隆

原图右下角有作者水印「Z」。处理水印的两条路：

方案适用代价
inpaint / clone 涂抹水印压在主体上、不能裁易留痕，参数难调
百分比裁切水印在画面边缘（底部中心/角落）几乎零成本，可参数化

水印在底部边缘 ~96% 高度，TRIM_BOTTOM = 0.06 先裁底再 cover-fit 到 3:4，水印连同冗余前景一起消失，主体不受影响。封面版和无字壁纸版共用同一个裁切参数，保证两张图主体一致。

完整排版流程（Pillow）

原图
 └─ 裁底去水印 (TRIM_BOTTOM)
     └─ 2× supersample 画布 (抗锯齿: 全程 2 倍尺寸, 最后 LANCZOS 缩回)
         └─ cover-fit 等比裁 3:4 (max scale + 居中裁)
             └─ 椭圆暗角 (只压文字角)
                 └─ 竖排中文排版
                 │    ├─ 主标题 牧云人  → 宋体 simsun (编辑感、清晰)
                 │    └─ 副标落款       → 楷体 simkai (柔、诗意) · 错落下沉
                 └─ 文字柔和投影 (由文字层 alpha 派生 → 染深色 → 高斯模糊 → 垫底)
                     └─ 缩回 1080×1440 导出

要点：

  • 竖排靠逐字 draw.text(anchor='mm') 按步长下落实现，不是一次画一串。
  • 投影别重画一遍文字：取文字层 alpha → point(v*0.6) 染深色 → GaussianBlur → 偏移垫在文字下。一行搞定，且压在亮处也读得清。
  • Windows 自带可用字体：宋体 simsun.ttc / 楷体 simkai.ttf / 等线 Deng*.ttf（拉丁小字用 Dengl.ttf 细体 + 字间距）。无思源宋体，别假设它在。

归档纪律（这次的运营教训）

  • 别把作品塞进语义不符的目录。一开始顺手建在 盘丝洞/，但那是”AI 女性写真”专属文件夹——独立作品要建独立编号项目目录（沿用 44_ / 45_ / 46_ 习惯）。
  • 标准结构：01_素材原图 / 02_成品封面 / 03_发布文案 / _脚本。
  • 一张原图可派生多个成品：带字封面（主图）+ 无字壁纸（多图第 2 张/下载钩子）+ 发布文案，都归同一项目目录。

如何使用

  • 下次”单张原图 → 小红书封面”直接拷 make_cover.py 改 SRC / 文案 / TRIM_BOTTOM。
  • 先肉眼看原图的留白在哪个角，文字和暗角就放哪个角；云朵/人脸/主体高光所在的区域不要压。
  • 水印先判断在不在边缘：在边缘 → 裁；压主体 → 才考虑 inpaint。
  • 找不到原图别死磕 temp → 直接做缩略接触表视觉检索。

封标要随主题切设计语言（2026-06-23 即兴抽卡 07/08 补充）

同一抽卡合集里，主题跳出古风时，别套用统一模板（宋体竖排+楷体+暖金那套是”古风专用”，套到时尚/暗黑题材会立刻失味）。做法：保留 cover-fit / 柔投影 / 2x 超采样 脚手架不变，只换文本层的设计，并先上网查该题材的成功封标范式：

  • 暗调戏剧（红衣裂面）：骨白宋体竖排主标 + 朱红细竖线（弃暖金）+ 朱砂方印（白字戏/面，simhei 实心字）+ 角落柔暗（右上强、向下 taper，护住下方面具/主体）。大留白 + 血红是这一路的张力来源。
  • 时尚编辑（白西装 OL）：仿 Vogue 封面——Playfair Display（Didone 高反差衬线）报头置顶（可半隐于发丝，正是 Vogue 标志性手法），衬线报头 + 无衬线封面语（Didot 小字会断笔，故封面语另用无衬线）。报头下加细横线 + 期号小字，刊名/署名压右下。

落坑提醒：

  • HYZhongHeiTi-197.ttf（汉仪中黑）缺大量中文字形，PIL 渲染中文会出豆腐块 □□□。要现代无衬线中文，用 msyh.ttc（微软雅黑） 才稳。
  • Windows 无 Didot/Playfair，需自取。Playfair Display 是 OFL，可 curl 直拉 Google Fonts 变体字（PlayfairDisplay[wght].ttf），Pillow≥8 用 font.set_variation_by_name('Black') 选重量；字体随项目存 _fonts/ 保证可复现。
  • 配套代码：{AIGC工作站}/48_即兴抽卡.../_build_covers_0708.py（mask / vogue 两套文本层 + numpy 角落渐变）。

深色背景的文字辨识度：柔投影会失效，改”柔光晕”（2026-06-25 噤声封面补充）

前文「文字柔和投影」是深字 + 同色偏移阴影——在亮背景上很好用。但封面文字压在深色/杂乱背景（如人物深发、暗调汉服）上时，柔投影直接失效：深影压深背景，对比还是不够，字糊成一团。先试”把字色加得更深”也救不回来——深字压深背景，加深没有意义。

解法：深墨 + 逐字柔光晕（halo）。不是在字下方偏移投影，而是给字铺一圈全向的浅色光晕把它从背景里”托”起来：

def _put(canvas, xy, text, font, fill, halo):   # canvas 为 RGBA
    layer = Image.new("RGBA", canvas.size, (0,0,0,0))
    ImageDraw.Draw(layer).text(xy, text, font=font, fill=fill+(255,))
    a = layer.split()[3]
    hc, hr, ha = halo                            # (光晕色, 模糊半径, 不透明度0-255)
    glow = Image.new("RGBA", canvas.size, hc+(0,))
    glow.putalpha(a.filter(ImageFilter.GaussianBlur(hr)).point(lambda v:int(v*ha/255)))
    canvas.alpha_composite(glow)                 # 先铺光晕
    canvas.alpha_composite(layer)                # 再压实字

判据（一句话记法）：

  • 背景亮 → 深字 + 柔投影（前文做法）
  • 背景暗 / 杂 → 深字 + 浅光晕（米白，半径≈字号 3%，副标题光晕做得更实更稳）
  • 浅字（如 HUSH 米白小字）→ 反过来配深光晕，浅模糊背景上也立得住

光晕半径别太大（会糊成一团雾），刚好够勾一圈边即可；它和柔投影是互补不是替代。

一张英雄图 → 多比例封面：按画幅分治（2026-06-25 噤声封面补充）

同一张原图要出 3-4 / 16-9 / 4-3 三比例时，别用同一种裁法硬套——按画幅取向分两套：

  • 竖屏满版（3-4）：竖图比 3:4 还窄时，收紧裁成贴脸特写，并把人物推向一侧、另一侧让出干净文字栏（前 3 秒识别度最高）。牧云人也是满版思路。
  • 横屏模糊填充（16-9 / 4-3）：竖条居中/靠右摆，背后垫同图放大 + 高斯模糊 + 压暗的虚化层，保留完整电影感构图与水墨留白。横屏强行 cover-fit 会把竖构图的头尾切光，模糊填充是更稳的解。

配套衍生招：采样复刻既有品牌。续做/改某系列封面时，先把旧封面裁出文字区 getpixel 取字色、比对字体、量版式坐标再复刻——比目测对齐快且准（字体尤其容易认错宋体分支）。

字位必须实测，不能目测（2026-08-20 雨里旧信补充）⚠️

来源：2026-08-20_雨里旧信_东方美人封面四轮复盘_v1。

前文说”先肉眼看原图的留白在哪个角，文字和暗角就放哪个角”。该案证明肉眼这一步会错——同一个判断错了两次（先判左侧，换素材后判右侧），实测才确认是左上灯光区。

人眼对”哪边看起来空”的判断会被主体位置的印象带偏；头发吹散、灯光晕开这类东西尤其骗人。

四步定字位

# 1. 8x8 亮度网格，看明暗分布
# 2. 暗部重心 → 主体偏哪边 → 文字放对角侧（见 [[封面对角平衡构图律_v1]]）
# 3. 候选字框扫描：算每个候选框的 mean + std，取 std 最低的
# 4. 落区亮度决定字色（见本文「深色背景」一节的判据）

第 3 步是关键。该案的扫描结果：

x60-460  / y150-380    L=242.7  std=18.7  ✅ 唯一干净框
x60-500  / y120-420    L=231.9  std=34.3  BUSY
x40-300  / y500-1100   L=179.8  std=27.0  BUSY
x60-460  / y1450-1750  L=156.4  std=28.1  BUSY

std 是干净度指标，mean 只说明亮暗。灯光晕开的区域 mean 很高但 std 也可能很高（渐变），要两个一起看。

⚠️ 两个配方别张冠李戴：该案给 L=243 的亮底误用了浅色阴影——浅光晕是暗底 / 杂底的配方。亮底走深字 + 深色柔投影，且亮底上只要一点点（半径 6、不透明度 80 量级），重了会脏。

顺带：能算出来的值不要留成参数

老唱片封套版式要求主标 / 细线 / 拉丁副名三者同宽、左右都齐。该案第一版把三者的宽度和字距各自手填，结果拉丁副名和中文主标对不齐——中文方块字与拉丁字母的自然宽度不同，任何手填字距都不可能刚好对齐，换个字号就又错开。

正解是主标宽度即本版「字宽」（measure），其余元素对齐到它，副名字距反算：

tracking = (measure - 自然宽度) / (字符数 - 1)

改完后把 rule.w 和 sub.tk 两个手填参数直接删掉。能算出来的值不要留成参数，它迟早会被填错。

边界：底图是纯色 / 大面积单调背景时，目测足够，不必跑扫描。

从单图排版到批量封面矩阵：版式必须先量后仿（2026-09-09 补充）⚠️

来源：给 Codex 做 aigc-topic-cover-factory skill，对标 65 张 B 站大字封面（10 份文案 × 5 张背景 + 正片 15 张，全 960×600）。

前文各节都是「一张英雄图 → 一张精修封面」。这次是另一种活：N 条选题 × M 张背景 = 可 A/B 的封面矩阵，单张质感不是目标，吞吐和可对比才是。版式因此必须参数化——而参数只能从对标里量，不能目测。

这是 2026-08-20_雨里旧信_东方美人封面四轮复盘_v1「字位必须实测」那条律的延伸：那次实测的是字位，这次把整套版式（字号 / 描边 / 行距 / 字距 / 色值）全部逐像素量了一遍。量出来的三条跟常识相反：

1. 层级靠颜色和行长，不靠字号（反直觉）

对标三行文案的墨迹高都是 75px——同一个字号。我第一版按常识「主标题该更大」实现，出来立刻是 PPT 标题页的味道。

这套版式的层级全由**「霓虹色 vs 白色」+「行的长短」**承担。字号一旦分主次，那股「信息流大字」的劲就没了。

2. 多行共用字号时，基准取 min 不取 max

每行先算「撑到自己目标宽度所需的字号」，然后取最小值作为全块基准。

取 max 会把短行算出的巨大字号套到长行上，长行直接冲出画布——第一轮渲染就是这么炸的。

3. 单行 ≤ 10 个汉字宽是几何约束，不是风格偏好

字号 ≈ 目标宽度 / 该行的 em 数
缩略图要可读 → 字号 ≥ 80 → 单行 ≤ 10 个汉字宽（"AI" 算 1.1 字）

超了排版救不回来，只能改文案。 所以这条得在写选题时就守住,不是排版阶段再补救——把它写进选题规范里,比写进排版脚本里有用。

三个实现坑

墨迹比要实测，别套通用值。 粗黑体汉字几乎填满 em 框：NotoSansSC 切 Black 实测墨迹高 ≈ 0.96 × 字号，且 anchor="lt" 时墨迹顶就落在绘制点上。我按常识给了 0.88 并额外上提 16%，行距全歪。正解是 font.getbbox(text) 取真实墨迹盒，别自己估。

逐字绘制必须分两趟。 要字距就得逐字画（Pillow 无 letter-spacing）。若每个字「描边 + 填充」一起画，后一个字的描边会啃掉前一个字的字面。正解：先把整行的描边画完，再画整行的填充。

蒙版必须羽化。 第一版用 rounded_rectangle 垫暗带，左右两条硬边一眼廉价，改高斯羽化才对。但更该记住的是：对标绝大多数图根本不上蒙版，只靠厚描边（≈ 0.075 × 字号）扛——描边才是这套版式的命根子，砍它等于砍掉整套版式。

验证招：拿对标图当背景复刻同一份文案

参数对不对，别用肉眼比。把对标图本身当背景，喂进自己的脚本复刻同一份文案——

  • 字压在原字上、几乎盖住 → 参数对了
  • 偏大 / 偏小 / 位置偏 → 一眼看出差在哪、差多少

比左右对照两张图准得多，也比量完就信要稳。这招同样适用于任何「仿一套既有版式」的活。
