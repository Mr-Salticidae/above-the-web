方向词要用既往选片反推

入档：2026-08-28 验证状态：⚠️ 首次立条（单项目三轮出图 + 四项目跨项目佐证） 来源：2026-08-28_试身_多风格人像_首轮收口复盘_v1 性质：AI 协作姿态律。管「作者给了一个方向词，助手该怎么把它译成参数」

一句话

「要视觉效果」「要高级」「要抢眼」「要氛围」这类方向词没有客观定义， 必须用作者既往的选片反推它在这个人坐标系里指向哪边—— 用通用摄影 / 设计常识去译，会自信地译反。

踩坑现场

作者原话：「不是特别高端的比赛，主打视觉效果」。

助手按通用摄影常识译成「高对比、硬光、抢眼」，据此改了三处： --stylize 从 50 提回 100（重心张提到 150）、把窗格光栅从”打在墙上”改成”爬到人脸和身上”、加 --hd。 文档里写的理由是「硬边光栅横切人脸是经典的高冲击人像手法，缩略图里也读得出来」。

实际结果：作者三轮留下的三张图，全部是柔光、高调、低对比、浅景深、朦胧。 助手押的硬光光栅三轮零命中。

跨项目佐证：不是单次偏好

项目影调
65_过风冷白高调，最暗处也没到纯黑
58_春信朦胧樱色
57_宿蝶暗调，但柔散光斑，不是硬光
68_试身柔光高调（三张）

同一个词，两个方向： 通用常识里「视觉效果」指向高对比 / 强反差 / 抢眼；这位作者的坐标里指向通透 / 干净 / 朦胧。

为什么这类错误特别难自查

  1. 方向词看起来像需求，其实是坐标。「要视觉效果」不是”做什么”，是”往哪个方向调”， 而方向必须有原点才有意义——原点是作者的既往选择，不是行业常识。
  2. 译错之后会长出一整套自洽的理由。本案助手为硬光写了骨架四层论证、缩略图可读性论证、 v8.2 顺风区论证——理由越自洽越难自查，因为每一条单独看都对。
  3. 参数错误会被档案挡下，方向错误只会被出图挡下。同一项目里，八处参数冲突在零出图成本处被知识库拦住； 这次方向错误一路走到出图才暴露——而出图是要花钱的那一步。

操作规则

  1. 拿到方向词，先不译，先找三张作者近期定稿的图。看它们在这个维度上的共同落点， 把方向词锚到那个落点上，而不是锚到行业常识上。
  2. 译完要把翻译本身摆出来确认，不要直接变成参数。 写「我把『视觉效果』理解成把对比拉高、让光更硬，对吗」比直接改 --stylize 便宜得多。
  3. 越是自洽的论证越要停一下。发现自己为一个方向写了三条以上互相支撑的理由， 先回头看那个方向是谁定的——是作者说的，还是自己译的。
  4. 落点是可查的，不要凭印象。作者的历史定稿在项目仓库里，翻三个项目的成图比猜快。

适用范围

  • ✅ 方向词：视觉效果 / 高级 / 抢眼 / 氛围 / 干净 / 有质感 / 大气 / 高端
  • ✅ 任何”往哪调”型指令：更冷一点、更克制、更年轻、更有故事感
  • ❌ 有客观标准的指令（比例、字号、时长、分辨率）不适用
  • ❌ 全新领域、作者没有既往作品可查时不适用——此时应当直接问，不要猜

边界

  • ⚠️ 单项目立条，跨项目佐证是影调这一个维度上的四个样本， 没有验证过其他维度（构图密度、色彩饱和、叙事直白程度）是否同样稳定
  • ⚠️ 作者的落点会变。这条说的是「先查再译」，不是「照抄历史」—— 查完发现这次要求和历史落点相反时，那是信号，该确认而不是该照译
  • 本条只覆盖”译错方向”，不覆盖”作者自己也没想清楚”的情形
