2026-08-24 《擦干净》从素材到动态化制片 · 全链路阶段性复盘

事实记录(不可修改区)

  • 作品名称:《擦干净》(B 站互动短片,悬疑/荒诞/社畜,主线 3:12 + 结局 A/B 各带 36s 片尾)
  • 项目/比赛:个人创作项目(非比赛,无票数/获奖结果)
  • 提交时间:暂未提交(本阶段仍在进行,v3 动态版主线性渲染中,4 张反转段素材因额度欠费待补,B 站互动配置未做)
  • 最终结果:阶段性收口,非完成态——素材/配乐/声音层/分镜重排/片尾已完成;动态化 13/17 镜头;成片 v1/v2 已渲染,动态 v3 渲染中
  • 数据来源:本会话交互记录(即梦 CLI 返回 credit_count/gen_status/ffprobe 校验/用户逐项裁决)

一、作品回顾

创作思路(项目既定)

21 岁末流本科毕业生林涛,公司”福利”VR 设备,虚拟世界里三个屏幕世界(老家/运动会/白领工位),反转揭示他被囚在培养槽里的大脑;观众在结局替他做选择(A 按流程清理/B 偷偷救它)。叙事核心:工具人共谋 + “你向往的自由,是被允许的自由”;主角全程失语;视觉系统=真实层 + 谷口治郎线条画拼贴。

执行过程(本阶段实际发生)

  1. 环境修复:read_image 不可用根因 = 服务真实 $DSH_HOME(C:\Users\Administrator.dsh)的 settings.yaml 未声明图像输入;工作区 .dsh-home 是误导文件,上一轮改错了位置;修正确认后配置热生效无需重启
  2. 素材生产:即梦 CLI 验证图(林涛背影/漂浮大脑)生成 → 我 AI 预判”通过” → 主创人工审图判”不过审” → 转 MJ 重出(回归 sref 体系,coffee cup 锚点 + Jiro Taniguchi)→ A/B/C 三批共 19 张素材全部过审(MJ 版)
  3. 人物设定修订(主创):21 岁末流本科毕业初入社会,穷但努力保持整洁;包工头改物业主管;手部埋点从”粗指节虎口疤”改”年轻干净手+指甲缝一点灰”
  4. 配乐:调研诺兰配乐方法论(声音=时间引擎/怀表 tick/Shepard tone/动机极简/音效乐谱化)→ SUNO 两阶段 Simple 探索 6 段 → 全部直接过审免 Custom;S4 反转段忘记开纯音乐模式,自动作词意外命中剧本(歌词”a hundred bells begin to chime”=伏笔回收) → 主创拍板启用带词版
  5. 音频先行重排分镜(主创纠正):音乐播完整片段,画面时长迁就音乐(谷底切分:58s 全曲最深谷=发现黑屏),原方案”音乐截 40s+淡出迁就画面”被否
  6. 声音层:ffmpeg 合成 18 音效 + edge-tts 5 句台词 + 4 段环境层,混音数据驱动
  7. 制片(图生视频):用户澄清”制片=Seedance 2.5 图生视频”;纠正”应使用全能参考(multimodal2video)而非首尾帧,1:1 资产可强制 16:9;720p 生成后期超分”;15 张并发提交,13 张 success,4 张 CreditPreDeductNotEnough 欠费
  8. 视频接入:初次渲染报 PIPELINE_ERROR_DECODE(seedance 输出 h264 High + AAC)→ 重编码 baseline/yuv420p/去音频/ASCII 文件名 → 修复

最终输出(当前)

  • 素材 19 张 MJ 定稿 + 动态视频 13 段(720p/16:9/4s,工程内 loop)
  • 成片 v2(静态+完整声音层)已渲染;v3(动态 13 镜头)渲染中
  • 片尾影视级署名:“AI 执行引擎:DeepSeek Harness”(主创定调:本片是 DSH 能力展示)

二、结果分析(区分主观判断与客观事实)

分镜我的判断主创裁决事实

经验教训(如实):我(AI)在三个环节做出了与主创相反的判断,全部被纠正——①AI 视觉预审可做事实级检查(无人体/文字可读/比例),但气质级判断(是否”廉价纪实质感/穷但整洁”)AI 会系统性高估通过;②对”制片”一词的项目语境理解偏差,未先确认就自行推进;③知识库已有的”音频先行”工作流我执行了(谷底切分),但擅自用”淡出迁就画面”违背其本意——主创裁决权 > AI 方法论演绎。

三、方法论沉淀

1. 图生视频接入 Remotion 的编码先决律 ⚠️首次

核心:生成式视频(即梦/Seedance 等)输出若为 h264 High profile + 内嵌 AAC,Remotion/Chromium 渲染必报 PIPELINE_ERROR_DECODE;接入剪辑工程前必须重编码为 baseline profile + yuv420p + 去音频流 + ASCII 文件名。

来源:v3 渲染 frame 259 崩溃(seed_S03_房间.mp4),ffprobe 确认 High+AAC;重编码后通过。

验证状态:⚠️ 首次发现(1 次项目内验证)

操作规则:

  1. 下载生成视频后一律先 ffprobe 查 codec_name/profile
  2. ffmpeg -i in.mp4 -an -c:v libx264 -profile:v baseline -level 3.0 -pix_fmt yuv420p -r 24 -crf 20 in.mp4 标准化
  3. 文件名 ASCII 化(规避 staticFile URL 编码)
  4. 视频内嵌音频一律移除(混音由工程声音层负责)

反例/边界:若使用 Remotion Studio 手动预览可能正常,渲染时才报错——不能以 studio 预览通过为验收。

2. Seedance 2.5 全能参考工作流(成本与陷阱) ⚠️首次

核心:multimodal2video(全能参考)可显式指定 --ratio,1:1 输入也能出 16:9;720p=104 credit/4s,1080p=256;提交即预扣,余额不足任务 fail 于提交后(CreditPreDeductNotEnough),成功任务不返还;可并发多任务提交。

来源:S34(1:1)→16:9 成功;15 张并发,13 success/4 欠费 fail。

验证状态:⚠️ 首次(具体价格量级待多项目复测)

操作规则:

  1. 首帧图比例 ≠ 目标比例 → 用 multimodal2video 显式 --ratio
  2. 预算先行:任务数 × 单张价格,预留 10%;欠费任务先提交后失败,不自动排队
  3. 每张任务记录 submit_id 与 credit_count(付费记录)
  4. 生成后保持原素材兜底(欠费镜头静态图仍可出片)

反例/边界:不同档位价格未做时长梯度测量(4s 与 30s 单价关系未知);480p 未测。

3. AI 视觉预审 ≠ 主创审美裁决(气质级判断不可代理) ⭐⭐

核心:AI 看图可查事实(比例/文字/无人体/穿帮),不可判气质(“廉价感""穷但整洁""谷口治郎纯度”);主创裁决是唯一终审,AI 预审结论应标注”事实项通过,气质项待主创”。

来源:即梦两张验证图,我预判全通过,主创判”不过审”(发型/气质不符);MJ 版按主创新设定(整洁学生短发/贫而整洁)重出后通过。

验证状态:⭐⭐ 二次验证(知识库已有 素材审片也能蒙眼_盲选靠标题定案靠眼睛_v1 的”AI 不盲选素材”语境;本次补充”AI 看图但气质层仍不可代理”)

操作规则:

  1. 审图结论分两栏:事实项(客观可验)与气质项(主创裁决)
  2. 主创反馈细化 prompt 时,记录其”气质关键词”(如”穷但整洁”),转写进 prompt 目标层
  3. 修改需求(如”发型太乱”)优先提炼成 prompt 具体指令,不重跑同 prompt

反例/边界:纯事实需求(无人体/无文字/16:9)AI 预审可一票否决;主创明确”按事实标准”时例外。

4. 音频先行:画面时长迁就音乐完整段落 ⭐⭐

核心:短片配乐阶段,先定音乐完整段落(乐章自塌谷底为边界),画面时长按音乐时长重排分镜;音乐不因画面硬截,静默/抽走靠剪辑制造或让音乐自然收口。

来源:主创否决”音乐截 40s+淡出”方案,改为完整段(第二幕 59.75s/第三幕 58s)→ 分镜帧数按比例重排,音频与音乐逐一对位。

验证状态:⭐⭐ 二次验证(知识库 2026-07-14_vpn-guard从工具到宣传片_全链路复盘_v1 已有”音频先行”三原则)

操作规则:

  1. RMS 包络找谷底(乐章分界)作为可选段边界
  2. 画面时长=选定音乐段时长;分镜按叙事权重比例微调帧数
  3. 骤停/抽走等静默由剪辑(DROP/硬切)实现;常规收尾用短淡出
  4. 主创裁决”完整段落优先级 > 画面时长”时,先改画面,不动音乐

反例/边界:MV 等以音乐为骨的作品反例可能不同;叙事节奏是硬约束时音乐让步(主创裁决)。

5. 遗忘≠错误:Suno 自动作词的意外之喜(强化已有规律) ⚠️

核心:Suno 自由作词的输出可能远超预设;本次”忘记开纯器乐”反而产出与剧本同构的歌词(整层楼铃声/等待选择),成为全片最强声音设计意外。知识库 Suno_v5.5_行为规律_v1 已有”自由作词=创作者草案水平”判断,本案例为其创作路径补充。

来源:S4 反转段忘记开 instrumental,歌词逐句命中剧本伏笔;主创拍板启用。

验证状态:⚠️ 案例补充(Suno_v5.5 规律已有多案)

操作规则:无(规律已在库);本案例归档为”意外不立即否定,先听是否与主题同构”。
