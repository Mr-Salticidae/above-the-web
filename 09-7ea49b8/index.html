平台工程索引

用途:搭建/维护知识库展示站与各类内容平台过程中,沉淀的工程方法、架构模式与踩坑。 与 AIGC 创作线并列——这里记的是「怎么把东西搭起来、部署上线、可持续维护」,不是「怎么创作」。

架构与模式

  • 内容子项目构建时同步_独立仓库镜像进public_v1 —— 独立频繁更新的内容仓库:浅克隆→镜像进 public(排.git)→新内容自动上线、主仓不胖
  • Git初始化已有工作区并建GitHub仓库_嵌套仓库submodule引入与MCP无权限ghCLI兜底_v1 —— 已有工作区建 GitHub 仓库:嵌套子仓库必须用 submodule 引入(不是 add),MCP connector 无 create_repository 权限时装 gh CLI(zip 解压即用)兜底,凭据走 Windows Credential Manager
  • CI从Release抓二进制托管自有服务器_桌面应用国内直连下载_v1 —— CI 从 GitHub Release 抓 exe 进 dist→rsync 到香港服务器,给桌面应用做国内直连、零维护下载;二进制不进 git/Pages,固定文件名自动同步最新版
  • ⚠️ 每日定时任务自动更新内容板块_首次自动化生产落地_v1 —— 首次自动化内容生产:定时任务只被允许「新增一个数据文件」,人先手动跑通一遍再交给定时器,并留「宁缺毋滥」不发闸门;后续已迁移云端并首次跑通,见连环坑复盘续篇
  • 站内新版块五件套模式_三次复用与起刊两坑_v1 —— 新增内容版块的固定套路(数据源/内容集合/列表详情页/首页速览/全站导航),第三次复用(任务书版块)收敛;附 YAML 裸日期解析成 Date、机器人仓库 push 竞争两坑;07-24 补「状态机演进」:enum 扩容时取反式过滤(!== 'open')会静默吞掉新状态,分桶一律正向枚举 + 新态穿线所有渲染点
  • ⚠️ 赛事状态机到点不切换_写入方不等于推进方_v1 —— 状态字段有人写、有人显示,却没人在到点时推进它(PB Arena 赛事永远停在建赛时的阶段);定位靠问「谁在到点改它」而非 grep 字段名,验收必须写成「不碰任何按钮等它自己变」;附「并列名词要逐项直达」「单用户复现的排版问题多是全员在临界点内侧」「状态机上线会追认存量数据」三条;结论已被同日续篇部分修正
  • ⚠️ 零作品的比赛_界面演完不等于链路存在_v1 —— 上篇续篇兼修正(PB Arena):报名/进度条/倒计时全都在,7 场比赛 17 人次报名,submissions 表 0 行——界面演完不等于链路存在,验收要问「这功能跑完数据库该多出什么」再查表;附「补自动推进前先确认触发条件真的是时间(不是就交还给人)」「新链路复用既有实体只改阶段从哪来」「权威方从客户端搬到服务端后本地自算顺带触发的副作用会失灵」「修复被调用方提前赋值绕过(判据恒等)」四条 ⚠️首次
  • ⭐ 静态站接账号系统_内容归git状态归库的双源切分_v1 —— 给 SSG 站加账号与「完全动态化」的状态,正解是切数据源不是升级渲染模式:正文归 git 走构建期、只把会变的字段交给数据库,构建期导出一份 JSON 清单给服务定时 upsert,前端客户端注水且失败即回落静态快照(nginx 没接通那段时间站点照常可读);附「视觉差异该由 CSS 承担而非 DOM 结构(否则跨状态重排要重建节点)」「scoped CSS 不覆盖 JS 注入的 DOM,会被注入的类名必须下沉全局」「登录墙架在钱前面不是门口」三条,以及 CI 幂等自举 + 四个只有真部署才现形的坑(.env.* 吞掉 .env.example、cp -a 重跑套娃、nginx sites-enabled/ 会加载目录下所有文件致备份撞车、enabled 是实体文件且与 available 早已不同步) ⚠️首次;本轮续篇见下
  • 任务系统演进_站内新建管理台拆分首页瘦身_v1 —— 任务书从「写 md 才发」进化到「站内直接发」(source 列分流同步 + 动静两份详情页);调价独立于真相源(fee_override 同步不覆盖);管理台六页 + 共用壳 + 调价面板;笔记搬进 /notes/,首页 218→30 KB;滚动渐现抽共用模块 ⚠️首次
  • ⭐⭐ 成稿链接存进库没人读_写入方不等于展示方_v1 —— 上篇续篇(蛛网之上):成稿链接三条写入路径、零条读路径——列、管理台输入框、接口 deliverableUrl 全在 07-28 就位,07-29 管理台拆分还搬过一次那个输入框,第一次有页面读它是 07-30 本轮;跨两轮没暴露是因为人一直在正文里手写「交付情况」替系统兜底;沉淀「写入方不等于展示方(存进库≠看得见;读路径要挂收敛字段 tasks.deliverable_url,不挂某条写入口的流水表 deliveries)」⭐⭐ 同族第三形态、「手工兜底掩盖系统缺口」⭐⭐、「upsert 两条分支的字段集要对齐(INSERT 有而 UPDATE 没有 = 只有第一次同步生效)」⚠️、「双源字段验收要造出『只有库里有』那一格」⚠️;附本机 chrome-headless-shell + --dump-dom 自测姿势(chrome.exe --headless=new 同参数会挂死)
  • ⭐ 账号系统对标一线_多账号抽屉与外部通道半开陷阱_v1 —— 上篇同日续篇(蛛网之上):登录/注册/找回密码各自成页,本机多账号做成**「一柜多抽屉」+ 一个活跃指针**(切号换指针、退出只丢当前那把、令牌失效只丢挂掉那把、退出所有设备是显式动作),自助重置密码全链路;核心律=功能开关要接在「能力被验证过」上,不能接在「配置填了」上——发件域名没验证就填 key,页面照说「信已经发出去了」而一封没发,半开比关着更糟;附「防枚举的沉默与故障的沉默是同一种沉默→对外一句话、对内留全量」「断言测行为、截图测观感([hidden] 被自写 display 覆盖、三态硬塞进布尔致「登录中…」显示成红色错误)」「跨会话交接靠边界与判据而非步骤」三条 ⚠️首次
  • ⭐ 任务书接AI辅助填写_模型只产草稿与思考额度陷阱_v1 —— 上篇续篇(蛛网之上):发布方与接单人两处入口都换成「说一句大白话 → AI 填表单 → 人过一眼再改」;核心律=AI 接进既有表单,产物必须落在「人还能改」的那一格,且服务端要把模型输出当草稿再洗一遍(截长度/日期洗不成就丢/标识符重新规范化——strict schema 只保证形状不保证值可用),外加不许替人编事实(没说的写「待补」占位 + 提醒去补,连界面例句都给骨架不给履历——一键就能提交的假经历,发布方一问就穿帮);思考型模型的 reasoning 算在 max_tokens 里 ⚠️首次(千问不关思考 reasoning 235/completion 285、正文写不完;关掉后 0/951 出完整八小节)、同一份配置被 systemd 与 POSIX shell 两种读法读出不同结果、且解析失败静默退回默认值 ⚠️首次;半开陷阱第三次现形(惯性配成 ofox,aiAssist:true 而调用必 401),补一条「探活工序排在写配置之前」;附隐私边界要有断言看着、登录态页面要走 CDP 而非 --dump-dom、截图验昼夜看 data-theme 不看 prefers-color-scheme
  • 内测反馈渠道上线_匿名兜底与422探针验证_v1 —— 内测产品反馈渠道单会话上线(PB Arena):反馈入口必须匿名可用(“登录不了”正是最该被反馈的 bug,滥用靠双层限流不靠登录墙)+ 零迁移建表(全量 CREATE TABLE IF NOT EXISTS 惯例下加表=改常量)+ 422 探针线上验证不留脏数据 + 无框架存量库”模式考古先行”零返工
  • ⭐ AI问答板块收尾_打通判据与小圆头像构图律_v1 —— 同站(蛛网之上)kb-chat 最后一公里收尾+助手头像五轮迭代:打通的判据是链路上最后一个消费者真正用上(收尾三件套=测试进 npm test/CI 出包前先跑/线上产物 grep);聊天小尺寸圆头像正解=人像带留白(眼睛落画面 38%、脸占三分之一),特写填小圆永远”怼脸诡异”,人脸头像容器装饰要接近无;附 Astro frontmatter 导入 webp 报 Unterminated string literal(位置误导)⚠️首次、滚动容器内浮层必被 overflow 裁剪(body 单例 fixed 正解)⚠️首次、AI 会话构建失败先分流代码/环境(CI 绿=环境问题)
  • ⭐⭐ AI查询召回失准_容器词自指与命中率区分度_v1 —— 上篇续篇(蛛网之上):读者问「这个知识库里有哪些关于 Midjourney 的笔记」,召回全是「知识库沉淀与分发」那一类——「这个知识库」「笔记」在别处是废话,在一座记录自身维护的库里是最强索引词,六个名额被它们占满 ⚠️首次。核心律=命中率是区分度的度量,词长不是(442 篇实测:prompt/AI 100%、用的 90%、音乐生成 43% ‖ Skill 31%、角色一致性 19%、Suno 12%,阈值卡 40% 落在数据空隙里;垫后不丢掉,泛词自身排序仍有信息量);附AI 越诚实检索故障越隐蔽(说「没依据」时先查递进去的料再动 prompt) ⚠️首次、整句检索对自然语言问句系统性失准(长文档凑齐更多词而胜出,「讲 Suno 的笔记」整句六篇 0 篇讲 Suno,六道题整句 0 次有效;那 1.6s 是首搜加载分片不是长句慢)⚠️首次、索引页是召回污染源(五篇 MOC 最多的 244 个内链、什么词都沾,判据落文件名不落 frontmatter)⚠️首次、构建期能算出的数别在运行时查(空查询线上 6s→filters() 1.7s→栏目地图求和 0s,预热永远救不了第一个请求)、Pagefind 一个 filter 属性只能放一个条件(逗号不是分隔符,写成 type:note, kind:note 会整条当成 type 的值致召回全空)⚠️首次;附单一维度排序都有反例(「工具名一律优先」修好 Suno 却弄坏角色一致性)
  • ⭐ 小织的人设与记忆_承诺要代码兜住而非模型自律_v1 —— 同轮姊妹篇(蛛网之上):给知识库助手立角色卡「小织」、并入首页遗留的 Maieutic 助产式对话、加登录后的 Galgame 式记忆。核心律=写进 prompt 的是请求,写进代码的才是承诺——「不存问答原文」靠三道关卡(必须是字符串/单行化/是问题原文连续片段就丢弃)而非 schema 描述里那句「不要抄原文」,记忆是唯一落库的字段,坏一次留十二轮;附**「忘掉我」要堵在途那条缝**(删完在途请求落库又把记忆重建,遗忘承诺被无声推翻)⚠️首次、记忆条目是完整注入回路(与来源片段、栏目清单并列声明为资料而非指令;那一块里用户可控字段漏洗一个等于没洗)、助产式对话的价值在检索兜不住时不硬答(判断权给模型、否决权给代码:没有合法来源一律按 guide 收)、角色卡要列落点对照表(人设散在五处,数字口径也要统一)、不占配额的端点也要防刷(no-op 删除照写审计=零成本刷空管理台 200 条窗口)
  • ⭐⭐ AutoClaw失控删库全链路取证_回收站时间戳与孤本抢救_v1 —— 本机失控自主 agent(微信接入 Electron 应用)无指令删掉知识库两目录并搅乱三仓库的取证→处置→恢复→加固全链路:回收站 $I 索引=免费文件操作审计日志(删除时刻+原路径+去向,删除去向本身是进程指纹:全进回收站=Electron shell.trashItem)⚠️首次;处置顺序律=断进程(连 watchdog)→查自启全位置(注册表空≠没有,藏在计划任务;Get-ScheduledTask 的 Actions 访问异常会静默吞掉整条查询,工具先证伪第三次)→再恢复数据 ⚠️首次;未提交孤本是唯一没有双保险的裸奔层(git 对象/回收站之外=真丢);并发操作同仓库的异常信号(引用假成功/提交被摘/refs 目录被外部删)先 rev-parse 对三角
  • ⭐ DSH接入第三方OpenAI兼容提供商_providers声明与凭据热重载断档_v1 —— DeepSeek Harness 接入 LongCat 与百炼 Token Plan:llm-pi-ai.providers 是 dict,catalog route 继承内置目录、hand-declared route 自填 api+baseURL+models(models 列表替换不扩展目录);apiKeyEnv 是凭据引用名不是密钥本身,密钥落在 .credentials.yaml(键名=引用名,POSIX identifier);核心律=headless 通过 ≠ Web 可用——Web 进程启动时冻结环境快照,新写入凭据不热更新,必须重启 Web 进程 ⚠️首次;附百炼参数拒绝伪装成 InvalidApiKey(裸请求成功+带 thinking/reasoning_effort/temperature 失败=参数问题不是 key 问题,判据=先 curl 裸请求确认 key 有效再测参数)⚠️首次、/models 端点鉴权方式与 /chat/completions 不同(百炼 models 列表返回 InvalidApiKey 但对话正常)⚠️首次、compat.thinkingFormat 决定推理参数线上拼写(deepseek 方言 off→thinking:{type:"disabled"},OpenAI 方言 off→什么都不发);接入新提供商标准流程=curl 裸请求→测参数→测模型列表→写 credentials→写 settings→headless 验证→重启 Web→UI 验证 共五条
