Flova 平台档案：编排层不是模型层

入档：2026-08-08 触发：《1000人后室大逃亡》项目全链路走 Flova，回答「这平台什么来路、能力边界在哪」时做的一次全网背景调研。 性质：桌面调研（公开报道 + 官方文档），不是实测档。实测层看 08 分发区那篇使用教程与项目现场记录。 时效：资本与模型接入两栏变动极快，引用前先看日期。

一、它是什么

Flova 自称「全球首个一体化 AI 视频创作平台」，产品形态是视频创作 Agent 工作台，不是一个生成器界面。官方文档给的三个支点：

  • 项目级记忆：script / shot / media / edit 全程写进项目上下文，「你的反馈、修改、最终选定」会被记住；
  • 多版本管理：每个阶段可出多版比选，选定后的版本成为后续生成的前置；
  • Skills：把创作者自己的方法固化成可复用、可分享的技能包。

域名两个都在用：flova.ai（官网与 docs 的规范域名）与 flova.tv（同一产品，08 分发区教程里用的就是它）。

二、谁在做

创始人兼 CEO 郭列，履历是一条很清楚的「爆款 C 端产品」线：

年份事
2013创办脸萌
之后FaceU 激萌
2018FaceU 被字节跳动以 3 亿美金收购
字节期间孵化轻颜相机、剪映、醒图
2025离开字节，创业做 Flova

团队很轻：增长与商业化负责人瑞瑞尔（95 后）、Agent 产品负责人唐果（00 后）。

时间线：2025 年 5 月做 Demo → 9 月初开始产品测试 → 2025 年 10 月上线。

产品设计的学习对象不是同行视频工具，是 Claude Code 和 Codex——郭列的原话是「Coding 以及通用 Agent 确实在 Agent 上走得比较靠前，所以我们对 Coding 产品的设计会研究得多一点」。这解释了 Flova 为什么长成「项目 + 上下文记忆 + Skills + 多版本」这套形态：它是照着编码 Agent 的骨架抄的，不是照着剪辑软件抄的。用过 Claude Code 的人对它的交互直觉是可迁移的。

三、钱从哪来

两轮融资累计超 8000 万美元，投资方红杉中国 / IDG / 云九资本，被媒体称为「目前视频 Agent 产品的最大融资」。

但放进赛道看，这个数字很小。2026 年 7 月同期（单月赛道融资额超过过去两年总和）：

家融资备注
可灵 AI30 亿美元 A 轮腾讯 / 阿里云 / 百度同投，投后约 180 亿美元
生数科技（Vidu）5 个月三轮，超 50 亿人民币
爱诗科技C 轮 29.8 亿人民币投后超 20 亿美元
智象未来C 轮 15 亿人民币
Flova8000 万美元应用层，非模型层

另一个背景数字：字节 Seedance 月营收超 10 亿，份额超 80%。

→ Flova 是这场大战里的应用层小额选手，钱花在编排与产品，不在算力与模型。这不是缺点，是定位——但它决定了下面第四节。

四、跟别的平台什么关系

寄生 / 编排关系，不是竞争关系。Flova 不训练自己的视频模型。

类别它调用的上游
视频Seedance 2.0（字节）、可灵 Kling、Veo 3.1（Google）、Sora 2（OpenAI）
图像Midjourney、GPT Image
语音ElevenLabs
音乐Suno

宣传里的「智能模型调度引擎」= 按镜头描述自动派最合适的底层模型。郭列本人否认「聚合平台」的标签，理由是「做 Agent 产品，不是直接满足用户需求，是通过 Agent 去更好地满足」——这个否认针对的是产品价值，不是技术事实。技术事实上，上表里没有一行是 Flova 自己的。

与字节的关系值得单列：创始人出自字节、做过剪映，Flova 重度依赖字节的 Seedance 2.0，但公开资料里没有股权或合作关系，是独立创业公司。

五、可迁移的三条判据

1. 评估一个 AI 创作平台，先分清它是模型层还是编排层

因为两层的能力边界归属完全不同：

  • 编排层平台的死区、画质上限、涨价风险，全部由底层模型决定，不由平台决定。 说「Flova 做不出多人同框 / 画面内文字 / 精细手部」是不准确的表述，准确表述是「Seedance 2.0 这一版做不出」。
  • 由此推出一条实操结论：编排层平台的能力清单有保质期，上游换代它就变。凡是写进团队规范的「这类镜头默认劝退」，都要挂上「基于哪个上游模型的哪一版」这个前提，否则规范会在上游升级后无声地过期。
  • 反过来，编排层真正自己的东西是上下文、版本管理、Skills 和工作流——评估它值不值得用，应该只评这几样，画质好坏是在评上游。

2. 平台的原生一致性能力优先于 prompt 复述

Flova 主推的 Ingredients 360° 角色一致性（正背视图建角色后绕拍锁脸）、以及默认 skills 里「人物形象直接给四视图 + 自动追加负面词」，都是平台层机制。项目里已经有一套自建的锚点角色 / 四视图规范时，正确动作是把它喂进平台的原生槽位，不是在 prompt 里再文字复述一遍——后者是在跟机制抢方向盘（同 生成式vs编辑式工具选择律_v1 的逻辑：顺着工具的默认行为走）。

3. 供应链风险是叠加的，凭证必须自己留

用编排层平台 = 同时承受「平台自身」+「每一个上游」的风险。Flova 这一侧的具体风险画像：成立不到一年、上线不到十个月、融资体量在赛道里偏小，而使用者往往把整条创作链路压上去。

对应的动作只有一个方向——把回溯凭证留在自己手里：

  • 导出文件的原始文件名不许改（那串时间戳 + hash 是回溯生成记录的唯一凭证）；
  • 语音的 voice_id 定版后写进自己的文档（丢了，同一个角色下次生成就是另一个人）；
  • 素材与资产图的真源留在自己的仓库/表格里，不依赖平台的项目上下文长期存活。

六、边界与未验证

  • 全部为公开信息：官方文档、创始人访谈、财经报道。没有一条是实测。
  • 模型接入清单是宣传与媒体口径，各家报道的版本号互相打架（Kling 2.5 / 2.6 / 3.0 都有人写）。要引用具体版本号，以平台内当时的实际可选项为准。
  • **「Flova 会自动追加负面提示词」「一幕一个项目、项目记忆不跨项目」**这类现场行为来自使用侧观察，不在本档的调研范围内——那些属于实测层。
  • 判据 1 的「上游换代 → 平台能力清单过期」目前是结构性推理，尚无本库内的换代前后对照案例 ⚠️ 待验证。 → 2026-08-08 更新：对照案例已设计，尚未执行。 《1000人后室大逃亡》S43 长镜头（25 秒）在 Flova 上于 6.00/12.00/18.00 秒各硬切一刀，用三臂对照（Flova vs 即梦 Web vs 即梦 CLI 直连 Seedance 2.5）判定分段来自编排层还是模型层——正是本条缺的那个换代前后对照。设计与仪器见 2026-08-08_后室大逃亡S43长镜头_归因未遂与生死线次序复盘_v1，该次实际生成 0 次，结论待回填。 → 2026-08-25 回填（三臂只跑了一臂）：65_过风 项目用 LibTV CLI 直连 star-video2.5 代替 「即梦 CLI 直连」那一臂，单条 30s / 1080p 实测 0 处切点（scene>0.3 检测为空， 逐秒亮度单调平滑无跳变）。→ Seedance 2.5 本身不做 6 秒分段， Seedance2_5_行为规律_v1 §一那条据此作废、移出模型层档案。 ⚠️ 但本条判据 1 的验证仍未完成：Flova 臂与即梦 Web 臂都没跑， 所以「Flova 编排层切的」与「Flova 上游是 2.0、15s 上限被迫拆」仍未区分—— 也就是说下面那条推论没有被排除。最省事的判决实验：在 Flova 上跑一条 15 秒以内的镜头， 切 → 是编排层；不切 → 是上游版本上限，本条判据 1 反而被自己预测的误判验证。 ⚠️ 一个可能一步定案的推论：本档第四节记 Flova 上游为 Seedance 2.0，而即梦 CLI 的参数校验器写死 seedance2.0 系 → 时长 4–15s。25 秒的镜头在 15 秒上限的模型上必须被切。若属实，按判据 1 的措辞，准确表述是「Seedance 2.0 这一版做不到 25 秒单次生成」，而非「Flova 有问题」——这恰好是判据 1 自己预测的那种误判。但第四节的模型清单是桌面调研、非实测，所以这只是强先验，不是该次生成的事实。

如何使用

  • 有人问「Flova 是什么来路 / 靠不靠谱 / 跟可灵什么关系」→ 直接给第一、三、四节。
  • 要判断某个镜头做不做得出来 → 不要查本档，去查对应上游模型的行为档案（可灵Kling3_0_行为规律_v1 等）。本档只告诉你该去查谁。
  • 接任何一个新的「一体化 / 全流程 / Agent」创作平台时 → 过一遍第五节三条判据。
