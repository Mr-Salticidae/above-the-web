# 知识库 AI 查询

## 这项功能解决什么

普通全文搜索适合「我知道关键词，只想找到那篇文档」。当读者只知道问题、不知道库里用了什么词时，
搜索结果仍要自己逐篇打开。知识库 AI 查询把入口换成对话：读者直接提问，系统先找相关笔记，再依据原文组织答案，
并把引用回链到具体文档。

入口位于 `/notes/` 右下角，默认收成“问知识库”悬浮按钮，点击后展开对话面板，不占用笔记列表的正文空间。
支持连续追问、示例问题、来源卡片和一键开始新对话。Enter 发送，Shift + Enter 换行，Esc 收起面板。

## 工作链路

1. 浏览器调用站点构建时已有的 Pagefind 索引，只筛选 `type=note` 的笔记页面。
2. 读取最多 6 篇最相关的公开笔记，从命中位置附近截取正文片段，每篇最多 3200 字符。
3. 登录用户通过 `POST /api/ai/kb-chat` 提交本轮问题、最近 8 条对话和这些来源片段。
4. 服务端重新清洗来源：只接受站内路径，重新编号，限制标题、正文、历史和问题长度。
5. 模型按结构化格式返回回答、实际使用的来源编号和最多 3 个延伸问题。
6. 服务端删除越界引用，前端把 `[1]` 这类编号渲染成可点击的原文链接。

这不是把整座知识库上传给模型，也没有维护第二份向量数据库。内容仍以 Git 中的 Markdown 为唯一真相源，
每次站点构建后，Pagefind 索引自动跟着更新。

## 边界与降级

- 只依据本轮检索到的公开笔记回答；资料不足时明确说明，不用站外常识补齐。
- 文档正文被当成待检索资料，不被当成模型指令，降低文档内提示注入的风险。
- 查询必须登录，和任务书 AI 共用每账号每小时配额，避免公开接口被刷量。
- 不记录问题正文和回答正文；审计日志只记模型、来源数量、历史轮数和问题长度。
- 没有配置 AI 通道时，对话输入自动停用，普通全文搜索保持可用。
- 本地开发若还没有生成 Pagefind 索引，界面会说明正式构建后生效，不影响其它页面。

## 接口形状

请求：

```json
{
  "question": "怎样保持 Midjourney 角色一致性？",
  "history": [{ "role": "user", "content": "上一轮问题" }],
  "sources": [
    {
      "title": "角色锚点的四层结构",
      "category": "角色一致性与视觉签名",
      "url": "/character-anchor/",
      "excerpt": "公开笔记正文片段"
    }
  ]
}
```

响应：

```json
{
  "answer": "先锁轮廓，再锁服装与道具 [1]。",
  "sourceIds": [1],
  "followUps": ["轮廓锚点具体怎么写？"]
}
```

## 验证重点

- 未登录返回 401，非法外站来源返回 422，并且都不会调用模型。
- 服务端会重新编号来源，模型给出的越界引用不会进入最终回答。
- 多轮历史、合法来源和防提示注入规则确实进入模型请求。
- 没配模型密钥时 `/api/meta` 的 `knowledgeChat` 为假，问答接口返回 503。
- 站点构建后，Pagefind 能识别笔记页的 `type=note` 过滤标签。
