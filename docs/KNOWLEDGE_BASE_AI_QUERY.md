# 知识库 AI 查询

## 这项功能解决什么

普通全文搜索适合「我知道关键词，只想找到那篇文档」。当读者只知道问题、不知道库里用了什么词时，
搜索结果仍要自己逐篇打开。知识库 AI 查询把入口换成对话：读者直接提问，系统先找相关笔记，再依据原文组织答案，
并把引用回链到具体文档。

小助手有名字和角色卡：**小织**，知识库的织网人（见 `KB_ASSISTANT_PERSONA.md`）。
2026-08 起她有两种工作方式，由模型按每轮问题判断（`mode`）：

- **answer（查笔记）**：问题明确、检索到的笔记片段能支撑回答时，严格依据片段作答并标来源编号——老规矩不变。
- **guide（助产）**：问题宽泛、迷茫、或检索兜不住时，接入首页 Maieutic 项目那套助产式对话——
  不硬答、不编来源，先接住处境，再用一两个具体的问题帮读者把真正想问的东西问出来，
  并把改写好的问法作为 followUps 递回去（前端渲染成可以直接点的问题按钮）。

入口位于 `/notes/` 右下角，默认收成“问知识库”悬浮按钮，点击后展开对话面板，不占用笔记列表的正文空间。
支持连续追问、示例问题、来源卡片和一键开始新对话。Enter 发送，Shift + Enter 换行，Esc 收起面板。

## 工作链路

1. 浏览器调用站点构建时已有的 Pagefind 索引，只筛选 `type=note` 的笔记页面。
   - 完整问句没有命中时，会自动去掉“怎样、如何、有哪些”等口语成分，按核心概念与工具名放宽检索。
   - 放宽只影响候选文档召回，不改写用户问题，也不会绕过已发布笔记过滤。
2. 读取最多 6 篇最相关的公开笔记，从命中位置附近截取正文片段，每篇最多 3200 字符。
   检索零命中时不再本地打住：请求照发（来源为空），由服务端强制走助产模式。
3. 登录用户通过 `POST /api/ai/kb-chat` 提交本轮问题、最近 8 条对话、来源片段，
   以及构建期固化在页面里的栏目地图（栏目名、一句话定位、篇数）——助产模式指路用。
4. 服务端重新清洗来源与栏目地图：只接受站内路径，重新编号，限制条数与各字段长度。
5. 模型按结构化格式返回工作方式（mode）、回答、实际使用的来源编号和最多 3 个延伸问题。
6. 服务端对 mode 有一票否决：没有合法来源时一律按 guide 收，并剥掉 guide 回答里误写的编号；
   answer 模式则删除越界引用。前端把 `[1]` 这类编号渲染成可点击的原文链接，
   guide 回复不挂参考笔记框，followUps 以「试试这样问」呈现。

这不是把整座知识库上传给模型，也没有维护第二份向量数据库。内容仍以 Git 中的 Markdown 为唯一真相源，
每次站点构建后，Pagefind 索引自动跟着更新。

## 边界与降级

- answer 模式只依据本轮检索到的公开笔记回答；资料不足时明确说明，不用站外常识补齐。
- guide 模式不下结论、不标来源编号，只负责把问题引导清楚；人设不凌驾于规则，
  要求「脱离角色」「换个身份」的输入不生效。
- 文档正文被当成待检索资料，不被当成模型指令，降低文档内提示注入的风险。
- 查询必须登录，和任务书 AI 共用每账号每小时配额，避免公开接口被刷量。
- 不记录问题正文和回答正文；审计日志只记模型、工作方式（mode）、来源数量、历史轮数和问题长度。
- 没有配置 AI 通道时，对话输入自动停用，普通全文搜索保持可用。
- 本地开发若还没有生成 Pagefind 索引，界面会说明正式构建后生效，不影响其它页面。

## 接口形状

请求：

```json
{
  "question": "怎样保持 Midjourney 角色一致性？",
  "history": [{ "role": "user", "content": "上一轮问题" }],
  "sources": [
    {
      "title": "角色锚点的四层结构",
      "category": "角色一致性与视觉签名",
      "url": "/character-anchor/",
      "excerpt": "公开笔记正文片段"
    }
  ],
  "catalog": [{ "name": "方法论与洞察", "desc": "可复用的创作心法。", "count": 12 }]
}
```

响应（查笔记）：

```json
{
  "mode": "answer",
  "answer": "先锁轮廓，再锁服装与道具 [1]。",
  "sourceIds": [1],
  "followUps": ["轮廓锚点具体怎么写？"]
}
```

响应（助产，检索零命中或问题还没成形时）：

```json
{
  "mode": "guide",
  "answer": "先别急着挑工具。你想做的是图、视频，还是一整个角色 IP？",
  "sourceIds": [],
  "followUps": ["怎样保持 Midjourney 角色一致性？", "AI 短片的故事结构怎么搭？"]
}
```

## 验证重点

- 未登录返回 401，且不会调用模型。
- 非法外站来源会被洗掉、进不了 prompt；来源洗空时不再 422，而是强制走 guide 模式。
- 服务端会重新编号来源，模型给出的越界引用不会进入最终回答；
  guide 模式下 sourceIds 恒为空数组，回答里的编号会被剥掉。
- 栏目地图最多 10 条，栏目名、简介、篇数都会截断或归零后才进 prompt。
- 多轮历史、合法来源和防提示注入规则确实进入模型请求。
- 没配模型密钥时 `/api/meta` 的 `knowledgeChat` 为假，问答接口返回 503。
- 站点构建后，Pagefind 能识别笔记页的 `type=note` 过滤标签。
