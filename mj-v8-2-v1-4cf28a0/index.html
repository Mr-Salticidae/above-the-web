MJ v8.2 行为档案

入档：2026-07-03 触发：49_凝视_写实重置 EP02 VESPER 开工，v8.2 首次实测（两批 11 张） 关联：MJ_v8.1_无oref_混合工作流_v1 / 新模型试跑_硬锁清单先行_v1 / 角色一致性金字塔_v1

一句话

v8.2 已于 2026-07-24 正式发布，调用从 --preview 转为 --v 8.2；写实人像质感较 v8.1 再上一档；异色瞳等”具体色名直给”类硬锁一句话即可稳定命中，配 sref 可跨批续接质感。但官方审美取向明确偏”抢眼”，克制 / 冷调 / 近单色项目需反向压制。

调用方式 ⚠️2026-07-24 变更

正式发布后：prompt 末尾写 --v 8.2。--preview 是发布前的临时通道，已完成使命。

历史（2026-07-03 ~ 07-23 preview 期）：prompt 末尾加 --preview 路由到 v8.2 预览模型，实测搭配 --ar 9:16 --raw --hd --preview、--ar 3:4 --preview --style raw。本档案第 1–4 条实测行为均在此通道下取得，正式版复测前视为仍然成立。

参数体系整体向后兼容：--sref / --sw / --style raw（--raw）/ --no / --stylize / --chaos / --profile 全部保留，prompt 库不需要重写。

实测行为（49 EP02 · 单项目样本）

1. 写实质感 ⚠️首次

老 prompt（半写实厚涂词系 semi-realistic anime illustration style, painterly rendering）直跑，出图质感即达”发丝级细节 + 真实皮肤过渡”，明显优于同 prompt 在旧版本的表现。质感提升不挑词系——连非写实词系都被拉高。

2. 异色瞳一句直给稳定命中 ⚠️首次（6/6，样本小）

one cold ice-blue eye and one warm rose-pink eye
  • 写法要点：左右 + 冷暖 + 具体色名，不写抽象单词 heterochromia
  • 单批 6/6 全中，预备的 --no matching eye color, symmetrical eyes 双保险未动用
  • 边界：双眼均清晰可见的近景构图下验证；侧脸 / 遮挡构图未测
  • 旧版本经验（异色瞳老大难、需负面词双保险 + 局部重绘兜底）在 v8.2 上疑似过时，待跨项目再验

3. sref 跨批质感续接 ⚠️首次

改 prompt 变量（本次改瞳色短语）时 sref 上一批成品图，新批与旧批视觉无断裂——“修 bug 不丢手感”。分工理解：sref 管质感氛围，不管脸的一致性（锁脸仍走 角色一致性金字塔_v1 的描述锚定 / oref 路线）。

4. 非人像场景质感 ⚠️首次（闪电战单样本 · 2026-07-16）

「同根同源」闪电战《七步诗 · 空屋火影》：古代灶间写实场景（土墙颗粒 / 火光层次 / 蒸汽体积感 / 硬光影子）一版立住，写实底座直接撑起影子叙事的可信度。参数组合 --ar 3:4 --preview --style raw 可用（与本档案人像侧的 --raw --hd 并存，未见冲突）。影子形态指令 shadows clearly shaped as ... 命中但形态偏离（two little brothers → 一大一小身影），属「偏离即升级」。详见 2026-07-16_同根同源_七步诗空屋火影高票复盘_v1。

5. 未测项（占坑）

  • v8.2 是否支持 oref / cref（v8.1 不支持，见 MJ_v8.1_无oref_混合工作流_v1）
  • --stylize 响应曲线（正式版下重开，44_异常值 已挂测试，见下）
  • 静物 / 特写题材的质感增益（场景已开测，见第 4 条）
  • 正式版 --v 8.2 与 preview 通道产出是否等价（本档案第 1–4 条需复测）

6. 要图标不要字：--no 四词法 ⚠️首次（闪电战单样本 · 2026-08-06）

PB 闪电战「时间贫困」回转寿司图。需求矛盾：盘沿贴纸上要出现抽象几何图标，同时全画面零文字（日料店的招牌与菜单是高危背景）。

有效写法：

--no text, letters, words, numerals
  • ⚠️ logo 绝不能进 --no——会把要保留的图标贴纸一起压掉。挡字形靠 text / letters / words / numerals 四个词就够
  • 真品牌 logo 不点名就不会自己长出来，不需要负面词防守
  • 正向侧配合：a different small round printed sticker showing a simple flat abstract geometric app-icon mark, flat solid colours, no letters no words + 列举 4–6 个具体形状（spiral / hexagon / triangle / sail / circle with a dot / asterisk）

结果：全图零字形崩坏（含背景菜单区）；传送带盘沿的图标造型干净、彼此不重复，every icon different from the last 命中。

结论：抽象几何图标是替代真品牌 logo 的可行路径——MJ 画不出可识别的真 logo，只会给融化的伪字形，在同行互投场上是最扣分的元素（一眼「AI 做的」+ 白送破解感）。

边界：写 each plate rim carrying...（“所有盘子”）时，MJ 只在未被遮挡的盘子上执行——堆叠盘的盘沿被遮，图标全落到了传送带上。图标位置不可控，要靠构图主动把带图标的物件放进视觉重心，否则唯一承载语义的元素会待在没人看的角落。同案复盘见 载体默认语义反噬_v1。

7. 长骨架可以在无 sref 条件下锁住一致性 ⚠️首次（单项目 4 张 · 2026-08-23）

PB 主持控场卡四张底图。完全没挂 --sref，四条 prompt 只共用同一句 103 词骨架、各换一句变量从句；四张各跑一个 job，零重跑零丢弃，prompt 原样粘贴。

结果：装置锁住了，景观没锁住，而且和篇幅正相关——

骨架成分词数四张实测跨度
装置（弧面 CRT + 底部控制台条）53（占骨架 51%）控制台顶边 10 个点（83.0–93.0%）
地平线10（占 10%）地平线 26 个点（53.0–78.9%）

结论：第 3 条说的”sref 管质感氛围续接”仍然成立，但不等于一致性只能靠 sref。当骨架里”要锁的那个东西”写到材质+形状+部件+排布四层，同一句骨架本身就是锚。细化沉淀见 骨架篇幅即权重_v1。

边界（重要）：

  • 本次没做 A/B（没跑挂 sref 的对照组），只能说明”不挂也成立过一次”，不能说明 sref 无用
  • personalization（--p）开关未确认，是最大的未控变量
  • 题材限定”同一装置的四种状态”；人物锁脸不适用，仍走 角色一致性金字塔_v1

8. 相对尺寸 / 位置词是弱信号 ⚠️首次（同批 · 2026-08-23）

同一批图里，very narrow horizontal strip 意图是 ≤7%，四张全出到 ~17%，且偏差方向完全一致——不是随机漂移，是 MJ 对 “narrow” 有自己稳定的理解。同句 prompt 里的 across the lower third 也没守住，一张跑到了 53%（画面正中）。

narrow / thin / small / low / lower third 这类相对尺寸与位置词，MJ 不按人心里的比例执行。属 MJ关键属性三重锁定律_v1 的跨项目新样本，把该律从”年龄 / 衣着 / 新旧”扩到了”尺寸 / 位置”。

修法：要么给画面内参照物（no taller than one knob），要么——本案的选择——出图后量，让下游排版适配，不为尺寸重 roll。

9. 自然语言 no 与 --no 参数分工不同 ⚠️首次（二十八宿星官单样本 · 2026-08-24）

一条 prompt 末尾用自然语言 no phoenix, no red, no orange, no warm colors, no Western features, no photorealism, no 3D, no anime（不是 --no 参数），同一张出图里：

自然语言 no结果
no phoenix✅ 命中 —— 出的是鸡不是凤，尽管尾羽极凤
no red, no orange, no warm colors❌ 失守 —— 唇是明确的橙红

结论：自然语言 no 对物种 / 物件这类可离散命名的实体有效（MJ 读成”画鸡不画凤”的选择题），对颜色这类连续属性无效。颜色要压必须走 --no 参数，或用正向色卡挤占。

⚠️ 但这次失守是资产：那点橙红是全图唯一暖色，落在视觉焦点上，撑起整张冷调图的体温。用 --no red, orange 硬压掉画面会变平。见 默认落点的资产负债判断_v1。

同批附带的构图结论：黑底是「辉光 / 神性」题材的总开关。白底 ＋ 平涂 ＋ soft divine glow 是三个互斥诉求（辉光在白底必糊、平涂拒绝渐变、神性要靠辉光），换黑底三者同时和解，背景不确定性也归零（强于任何 --no busy background）。

⚠️ 由此纠正一处易犯的连锁误判：本档「克制 / 冷调 / 近单色 / 大留白项目要反压 --stylize」是按画面取向判的，不是按背景颜色判的。黑底 ＋ 强辉光属于 v8.2 的顺风区（bold / 强对比），默认 --stylize 100、不加 --style raw 即可；把”白底”读成”克制”会把参数调反。

来源：2026-08-24_二十八宿星官_黑底探索与一次结论作废复盘_v1

10. --profile 尾巴可把画种整体翻转，明确媒介词 + 自然语言 no 都挡不住 ⚠️首次（受控 7/7 · 2026-08-24）

二十八宿星官 A/B：昴日鸡 prompt 逐字相同、seed 42/43 配对、都带 --hd --v 8.2，唯一变量 --profile qwksp9b dsdxtdr（personalize ＋ 美女写真 moodboard 合挂）。

组画种
无 profile（8 张）中式插画 8/8 —— 与 prompt 一致
挂 profile（7 张）写实摄影 7/7

prompt 里防守画种的全部手段——正向 Chinese hand painted flat illustration, gongbi inspired fine linework, mineral pigment palette ＋ 自然语言 no photorealism, no 3D——全数失守。同批红色像素约 7 倍（红鸡冠 / 正红唇出现），no red, no orange, no warm colors 被击穿得更彻底；黑底 / 主体 / 构图守住。

结论：profile 尾巴的拉力在媒介层强于 prompt 正文。非摄影题材（插画 / 平面 / 图解）挂写真系 profile 尾巴 = 画种直接被拖走，先摘尾巴再调词。

边界：两码合挂未隔离（翻转归 personalize 还是 moodboard 待单挂 A/B）；--no photorealism 参数形态未测（本次是自然语言 no）。详见 2026-08-24_二十八宿星官_黑底探索与一次结论作废复盘_v1，归类框架 moodboard主体位判据_假说_v1。

11. 第 8 条的对策「给画面内参照物」——首次正向验证 ✅（人像三张 · 2026-08-28）

第 8 条实测相对尺寸 / 位置词是弱信号（across the lower third 一张跑到 53%）， 给的修法是「给画面内参照物」。本次首次正面验证：

❌ she occupies the right third of the frame
✅ she is entirely to the right of the window and does not overlap it

三张成图全部命中，人都完整落在窗右侧、无一张与窗重叠。参照物是画面里另一个被画出来的实体（窗）， 不是抽象方位。→ 该修法从”建议”升为有正向样本。

同批另外三条：

  • ❌ 空间关系句被场景几何否决。写死了四层的「光栅横切她的脸和身体」三张全部只落在墙上—— 因为同一条 prompt 里的站位句已经把人放在了光路侧面，两句话抢同一个几何，几何赢。 单独立条见 空间关系归几何不归形容词_v1（修法侧未验证）
  • 🎁 建筑构件术语有稳定的默认落点：a tall old wooden window with horizontal muntin bars（直棂） 三张全部出成 louvered shutter（百叶窗），一致，不是随机。且百叶的斜向密集光栅比原设计的横条 层数更多、更有纵深 → 判为资产，改写成 louvered shutter 锁死。 同批 practice leotard → 高开叉连体衣（芭蕾身份丢失）则是负债。 推论：写建筑 / 服装构件时先跑一张看它理解成什么，再定用哪个词，别假设术语准确。 资产负债判法见 默认落点的资产负债判断_v1
  • ✅ 装扮签名跨姿势跨景别 3/3：long straight jet-black hair, centre-parted, blunt-cut ends falling below the chest, worn loose 在三条不同 prompt、三种姿势、三种景别下四个限定全中， 给 装扮签名vs五官精度_v1 补样本

来源：2026-08-28_试身_多风格人像_首轮收口复盘_v1

12. --ar 只吃整数比，小数点直接拒跑 ⚠️首次（公众号封面配图 · 2026-08-31）

--ar 2.35:1 会被拒绝并报：

Aspect ratio should be of the format width:height

不是比例不被支持，是写法不被解析——MJ 的 --ar 只接受整数对，任何带小数点的写法都过不了参数校验。改成等价整数即可：--ar 235:100（或约分的 --ar 47:20），出图尺寸完全相同。

踩点场景是公众号首图（标准比例正是 2.35:1），同类高危的还有一切用”几点几比一”表述的电影画幅（1.85:1 → --ar 185:100、2.39:1 → --ar 239:100）。日常常用的 16:9 / 3:4 / 9:16 / 1:1 本来就是整数，所以这个坑只在做非标准画幅封面时才现形，平时跑图碰不到。

判据：凡是脑子里以「X.XX 比 1」形式记住的比例，写进 prompt 前先乘 100 化成整数对。

来源：08_对外分发/GPT和Codex一直转圈连不上_公众号配图MJ提示词.md

13. 四词法不是 100%，大面积纯色亮区是漏点；另 MJ 会随机给图套画框 ⚠️首次（公众号配图 8 张 · 2026-08-31）

同一批八张图，两个与交付直接相关的发现。

四词法的漏点在大面积纯色亮区。 挂了第 6 条的 --no text, letters, words, numerals，八张里七张零字形，唯一漏网的那张，伪字形漏在整块纯白屏幕上——而其余七张都没有这么大的无内容亮区。推测：大面积纯色会诱发它「填点什么」。

对策不是继续加负面词，是准备后期抹除。 底是纯色时 ffmpeg 的 delogo 插值一次就干净、无接缝：

ffmpeg -i in.png -vf "delogo=x=575:y=1130:w=900:h=85" out.png

判据：凡 prompt 里出现「大片白屏 / 纯色墙 / 空白招牌」这类无内容亮区，就默认它可能长字，交付前放大看一眼那块区域。

MJ 会随机给图套画框。 同批八张里有一张自带厚 132–134px 的均匀浅色外框（四边等宽），像被裱进相框，其余七张都没有。同一段骨架、同一组参数，属随机行为。带白边的图放进公众号 / 小红书正文会像截图，交付前逐张看四边，裁掉即可——用 crop 精确切：

ffmpeg -i in.png -vf "crop=2680:1380:132:134" out.png

第 8 条（相对 / 位置词是弱信号）本批第三次现形，且是新形态：「一个例外」也是弱信号。 prompt 写「一排灯全部亮着同一种冷白，只有队尾一盏是暗的」，出图是亮暗交替约各占一半——MJ 把「有一盏是暗的」泛化成了「有些是暗的」，整齐性随之丢失，语义直接反了（要的是「全都看起来没问题」，出来的是「部分故障」）。

修法与第 8 条同源但方向相反：那条的对策是「给参照物」，这条的对策是把例外整个删掉，让全称描述独占画面，另找元素承载那个例外要表达的信息。

14. 第 10 条的同向样本：CG 媒介词挡不住 --profile 把人像拉成写实摄影；隐形人台服装图会带出模特残留 ⚠️首次（76_清月 · 2026-09-25）

两件事，都来自同一项目的四张资产图（全部挂 --profile idsugkv ppbo4tu、无 sref、--hd --v 8.2）。

① 画种被拉向写实摄影（无对照）。 身份图 A01 的 prompt 开头就是 Premium Chinese 3D animated xianxia film still, high end CG render，中段写了 high crossed collar and gold filigree pauldrons visible。出图：

  • 画种偏写实摄影（接近 BJD / 写真质感），不是 CG；
  • 露肩、没有高领、没有袍——服装句整句没执行；
  • 银发、右眼下泪滴印、镂空冠 + 眉心珍珠这些面部与装扮签名都在。

与第 10 条方向一致（profile 尾巴的拉力在媒介层强于正文）。但这次没有去掉 profile 的对照组，服装丢失也可能是 chest up 近景构图本身的取舍，所以只算同向样本、不算二次验证。 后续处理见 Seedance2_5_行为规律_v1 第四节：进视频时裁到只剩头部，视频成片是 CG 质感，照片感没带进去（结尾一个与 A01 同景别的近景除外）。

② 隐形人台（ghost mannequin）写法：无头无脸成立，但带出模特残留。 服装资产 A04：

costume design asset, an ornate xianxia robe displayed on an invisible ghost mannequin with no head and no visible body, front view, the full costume visible from collar to hem, ...
--no text, letters, words, numerals, people, face, head
  • ✅ 无人、无脸、无头；高立领、镂空肩甲完全盖住双肩、过膝广袖、身后长飘带全中。
  • ❌ 领口到腰垂着几缕黑色长发；袖口旁露出一只苍白人台手。
  • 推测：ghost mannequin 仍会先画一个”人”再擦掉头脸，擦得不彻底。备好的补跑是 --no 加 hair, hands，未跑（作者裁定服装不进视频）。
  • 为什么这点要紧：服装图要挂进视频模型当参考，而参考图里的黑发会被照搬（Seedance 2.5 档第四节 ⭐⭐⭐）。

外部情报（2026-07-24 正式发布，非自测）

来源分级：官方＝Midjourney 发布公告 / release notes；三方＝社区实测文章，仅作假设，未经本仓库验证。

官方

  • 7/24 发布 v8.2，主打 aesthetics / image quality / personalization。原话：图会更 “creative, bold, sophisticated, edgy and fresh”，随机低质量图的概率大幅降低。
  • 6/25 Draft Mode 支持 --sref random ⚠️重要：一次出 24 张、每张一个不同的随机 sref 码，512×512，整批约 0.4 GPU 分钟。官方口径”style space 探索快 24 倍”。
  • 6/11 v8.1 转正为默认（替代 v7）；Draft Mode 于 6/16 随 v8.1 上线。
  • 官方公告未列任何参数变更。

三方（假设，待验证）

  • v8.2 比 8.1 更愿意留下强对比、非对称构图、粗粝质感。
  • --style raw 重要性上升——是对抗 v8.2 更强风格化的主要手段。
  • --stylize 需整体下调重新标定；--sw 可较 8.1 下调（style 匹配更准）；--chaos 较 8.1 低 10–20。

由此推出的工作流变更

1. 找锚流程改写（影响所有”先找 sref 锚再全片复用”的项目）

旧：--sref random 跑 4–6 次，人工挑。 新：一次 --draft --sref random 出 24 张，从中挑锚 → 记码 → 去掉 --draft 全质量复跑确认。样本量翻四倍，成本降一个数量级。

边界：draft 是 512×512 低质量，只能判色调 / 构图 / 氛围，判不了细颗粒度问题（如”一点红 vs 满屏泛红”这类颜色纪律）。这类验证必须全质量跑。

2. 克制型项目需反向压制 ⚠️

v8.2 的”bold / edgy / 强对比”取向，对克制、冷调、近单色、大留白的项目是逆风——模型默认往”更抢眼”推，正好是这类项目要躲的方向。这类项目升 8.2 不能只改版本号，要同时：--style raw 保留、--stylize 主动压到默认（100）以下、--sw 下调。

首个实践：44_异常值 风格基底（系统档案影像 / 近单色 / 红色严格配给），尾参定为 --v 8.2 --style raw --stylize 50、--sw 150。--stylize 50 vs 100 的对比结论回填本档案第 5 条。

换用建议

  • 写实人像项目：直接上 v8.2，老 prompt 可直跑试水，但入库前必须过角色卡硬锁清单（踩坑见 新模型试跑_硬锁清单先行_v1）
  • 需要锁脸的多镜头项目：v8.2 质感镜头 + 锁脸镜头分工的混合策略，沿用 v8.1 档案的 A/B/C 分类法
  • 克制 / 冷调 / 近单色项目：升 8.2 要连带压 --stylize，不能只改版本号（见「外部情报 → 工作流变更 2」）
  • 任何要锁 sref 锚的新项目：找锚一律先走 --draft --sref random 大批次，别再手动跑多轮
