教程类任务规范

接教程类任务前先读完这页。下面的标题命名、分享权限、上传流程和正文模板是交付验收的硬标准—— 不按这个结构走，返工的概率比你想象的高。

金额与时间不在这页

教程金额与审核时间每期不同，一律以对应任务书详情中注明的为准， 本页只管交付格式。

一、通用要求

1. 标题命名

教程标题统一为 XXX教程（名字-时间）。

例：Gemini 3 序列帧动画及应用制作教程（晓笙 25-11-25）

2. 分享权限

分享教程链接前，务必把权限打开到互联网上获得链接的人可阅读，否则对方点开是一片空白。

链接分享 → 互联网获得链接的人 → 可阅读

二、上传钉钉知识库

每次教程做完后，一定要上传到钉钉总知识库。 动手前先申请编辑权限，没有权限是填不进去的（需内部权限才能打开）。

第一步：新建

进入数据目录页，在左侧数据列表中选中「AI 自媒体教程文档」这张表，点击顶部的「添加记录」。

第二步：填写记录

新建出来的是一条「未命名记录」，把下面五项依次填完。

1. 名称——把教程标题填在「未命名记录」的位置，命名格式见上一节。

2. 简介——一句话说明这期教程做的是什么。

3. 图片——把成品图或封面图粘贴、拖拽进「图片」栏。

4. 链接——把教程文档链接填进「链接」栏。放之前先确认权限已开到「互联网获得链接的人可阅读」。

5. 分类——从下拉菜单中选择对应分类，不要留空。

三、AI 玩法类教程

正文按下面四节走。若教程涉及单个工具或多工具、提示词的横向对比，第二节标题改写成「测评对比」，不再写「软件说明」。

一、成品展示

一段话说明用什么工具、什么方法做出的成品案例，下方必须放成品截图或视频。

二、软件说明

每个工具一小节，格式为 1. xxx 工具——什么作用，正文一段话介绍工具，再配一张工具页面截图。例：

  • 1. gemini3 工具——制作 GIF 动画应用，配 gemini3 工具主页面截图一张
  • 2. Nano Banana Pro 工具——制作动画分镜图图片，配 Nano Banana Pro 使用主页面截图一张

二、测评对比（替代「软件说明」时用）

格式为 1. xxx 工具或提示词名字——什么作用：正文一段话介绍，再讲具体含义和应用， 配工具页面截图一张，以此类推。

三、操作流程

有网址的就带上「打开 xxx 网址」。按第一步、第二步、第三步逐条拆解，每步说明打开什么工具、起什么作用。

二级标题的格式必须是软件名称 + 用途，例：Nano Banana Pro 制作图片。

四、总结

图片 + 文字，讲清制作过程中遇到的困难点和需要注意的地方。

四、AI 工具评测类教程

评测类只需三节，结构比玩法类短。

标杆范例

问小白 5 Pro 测评教程 （Jane，2026-07-27 交付）经发布方评定为完成度与专业度最高的一篇； Flova 测评教程 （南山，2026-07-27 交付）同批收录，示范了 Agent 类工具从剧本到成片的全链路怎么拆步骤、怎么摆提示词原文； OJO 测评教程 （Jane，2026-07-30 交付）把三节体例执行得最规范，每一步都配图并在图上标出操作位置，总结落到具体结论。

三篇均为评测类教程的对标标杆， 动笔前先各通读一遍，照着这个完成度要求自己——下面的三节说明是底线，这三份范例是目标。

一、成品展示

一段话说明测评的是什么工具，配相关图片。若测评的是提示词，需给出提示词名称及中英文原文。

二、各步骤流程展示

按「工具展示步骤——对应作用」组织，逐步拆解。

三、总结图文

同样是图片 + 文字，讲清困难点与注意事项。

五、一条红线

涉及教程制作，一定要图片配文字。不要写「通常来说我们需要调试几次才会达到自己满意的效果」 这类大白话——空话没有意义，写了等于没写。
